## TICKET 1 — Ad landing pages serve the homepage's `<title>` and no canonical in raw HTML

**Priority:** P2
**Traffic at stake:** 2 GA4 sessions / 90d measured, but this is the destination surface for
the entire paid program, so measured sessions understate it. Stated as measured, not inflated.

**URLs**
```
https://baselayerskin.co/article/5-reasons
https://baselayerskin.co/article/2-minute-routine
https://baselayerskin.co/article/one-bottle-experiment
https://baselayerskin.co/article/peptide-stack
https://baselayerskin.co/article/concentration-test
https://baselayerskin.co/lp
https://baselayerskin.co/product/*
```

**Problem**

These routes are deliberately excluded from prerendering (`vite.config.ts:967-971`) and
rewritten to `/__shell.html` with a 200 status. The shell is a generic 8,171-byte SPA
skeleton that carries the homepage's title and no canonical:

```
$ curl -sSL https://baselayerskin.co/article/5-reasons | grep -o '<title>.*</title>'
<title>Base Layer | Men's Face Cream That Actually Works | $38</title>
```

All five advertorials do set their own title, description and self-canonical after
hydration via `useCanonical()` / `useMetaTags()` (`src/pages/advertorials/*.tsx`). Google
renders JS, so Googlebot sees the right head. Everything that does not render JS does not:

- Facebook, Instagram, X and LinkedIn link unfurlers. Every time one of these advertorials
  is shared or run as a paid placement, the preview card reads "Base Layer | Men's Face
  Cream That Actually Works | $38" instead of "5 Reasons Men Are Switching From Drugstore
  Face Creams". That is the hook the ad was written around, thrown away at the preview.
- The AI crawlers `robots.txt` explicitly invites (GPTBot, ClaudeBot, PerplexityBot,
  CCBot, and the rest). All five advertorials currently present to them as the homepage.

This is the same dual-writer `<head>` class of bug already documented in
`kb/wiki/technical-seo.md`. The prerender half and the React half disagree, and only the
React half is correct.

**Fix**

The prerender pipeline already works (fixed 2026-08-17 in `ff8ba06`). Add the six client-only
routes to the prerender list in `vite.config.ts` and drop the corresponding
`/__shell.html 200` rewrite lines, so they ship a real head like every other route.

Keep them out of `sitemap.xml`. Prerendering and sitemap inclusion are separate decisions,
and advertorials should stay out of the sitemap.

Decide explicitly whether these should be indexable at all. They currently self-canonicalize
with no `noindex`, so they are eligible. If the answer is no, the fix is one line in the
shell rather than prerendering — but the social preview problem stays broken in that case,
so prerendering is the better answer either way.

**Verify**
```bash
curl -sSL https://baselayerskin.co/article/5-reasons | grep -o '<title>.*</title>'
# expect: 5 Reasons Men Are Switching From Drugstore Face Creams
curl -sSL https://baselayerskin.co/article/5-reasons | grep -o '<link rel="canonical"[^>]*>'
# expect: self-canonical, present in raw HTML
```

## Appendix — findings with zero traffic and zero impressions

Real, but nothing is at risk today. Fix opportunistically.

- **5 redirect chains (2 hops each) through `/blog/*`.** `/blog/3-step-skincare-routine-men`,
  `/blog/skincare-ingredients-that-work`, `/blog/post-shave-recovery`, `/blog/razor-burn-guide`
  and `/blog/skin-barrier-guide` each hit the `/blog/* → /articles/:splat` wildcard first, then
  the article-slug rule. Netlify takes the first matching rule, so adding the five explicit
  `/blog/<old-slug> → <final> 301` lines above the wildcard in `public/_redirects` collapses
  every one to a single hop. Zero GA4 sessions, zero GSC impressions on any of them.

- **One internal link to a 301.** `/articles/the-ultimate-3-step-skincare-routine-for-urban-commuters`
  links to `/skin-concerns/barrier-damage`, which 301s to `/skin-concerns/dry-dehydrated-skin-men`.
  Point the link at the destination. Source page has zero sessions and zero impressions.

- **`/product/*` is an open 200 wildcard.** `/product/anything` returns the SPA shell with a
  200 rather than a 404, so unknown handles are soft-404s. Nothing links there and the plural
  `/products/*` correctly 301s to `/face-cream`, so exposure is zero. Worth closing if the
  advertorial prerender work in Ticket 1 touches this block anyway.

- **`scripts/generate-sitemap.mjs` is dead code.** It writes 56 URLs to `public/sitemap.xml`
  and is always overwritten by the Vite plugin's 60. Harmless today, ships a stale sitemap
  the day the plugin ever bails early. Delete it.
